## Introduction

Before taking this course, I had very little experience using UI frameworks such as Bootstrap 5. Most of my previous experience with web development involved writing raw HTML and CSS, where every element and style had to be created manually. At first, Bootstrap seemed unnecessarily complicated. Rather than making web development easier, it often felt like I had to learn an entirely new language just to accomplish tasks I already knew how to do with HTML and CSS. However, and with my short time but rigorous testing of Bootstrap, I began to understand why frameworks are so widely used. While they require a significant investment of time and patience to learn, UI frameworks provide many advantages that make developing and maintaining websites more efficient, especially on larger projects.

## Learning Bootstrap

One of the biggest challenges I experienced while learning Bootstrap was understanding how its layout system works. With raw HTML and CSS, I was used to positioning elements however I wanted and creating my own styles from scratch. Bootstrap introduced concepts such as containers, rows, columns, utility classes, and responsive breakpoints, all of which had their own rules and conventions. There were many situations where I knew exactly how I wanted my page to look but struggled to figure out which Bootstrap classes would produce that result.

Throughout several assignments, I found myself frequently referring back to the Bootstrap documentation or asking questions whenever my layouts were not behaving as expected. Small mistakes, such as using the wrong container class or misunderstanding how the grid system worked, could completely change the appearance of a page. At times, using Bootstrap actually felt more difficult than simply writing the CSS myself. Despite these frustrations, I eventually became more comfortable reading Bootstrap code and understanding how different classes worked together. Rather than memorizing every class, I learned to recognize common patterns that appeared across many Bootstrap websites.

## Bootstrap Compared to Raw HTML and CSS

Although Bootstrap can initially seem more complicated than writing raw HTML and CSS, I believe it offers several advantages once you become familiar with it. One of its biggest strengths is consistency. Instead of creating styles for every button, navigation bar, spacing value, or layout from scratch, Bootstrap already provides professionally designed components that work together.

Another major advantage is responsive design. Before using Bootstrap, creating websites that worked well on different screen sizes required writing numerous media queries and adjusting layouts manually. Bootstrap handles much of this automatically through its responsive grid system and utility classes. This made it much easier to build pages that looked acceptable on both desktop and mobile devices without having to completely redesign the page.

I also noticed that Bootstrap encouraged me to organize my HTML more carefully. Since many components rely on a specific structure, I had to pay closer attention to how different elements were nested together. While this sometimes made debugging more difficult, it also resulted in cleaner and more organized layouts.

## The Software Engineering Benefits

Beyond simply making websites look nicer, I believe UI frameworks provide several software engineering benefits. Since Bootstrap follows a standardized set of components and naming conventions, it becomes much easier for multiple developers to work on the same project. If everyone uses the same framework, developers can often understand each other's code more quickly because the structure is familiar.

Another benefit is reducing repetitive work. Without a framework, developers often rewrite the same CSS for buttons, navigation bars, forms, spacing, and layouts across multiple projects. Bootstrap eliminates much of this repetition by providing reusable components that have already been tested across different browsers and devices. This allows developers to spend more time focusing on the unique aspects of their project instead of repeatedly solving the same design problems.

I also think frameworks make maintaining projects easier. If changes need to be made later, developers can often update existing Bootstrap classes instead of rewriting large portions of custom CSS. This can make projects easier to manage as they become larger and more complex.

## On the Contrary

Despite these advantages, I still believe there are situations where raw HTML and CSS may be the better choice. For smaller websites or personal projects, Bootstrap can sometimes feel excessive. There were several occasions during this course where I already knew how to accomplish something with CSS but instead had to spend additional time figuring out the Bootstrap approach. In those moments, the framework felt more like an obstacle than a helpful tool.

I also found that relying too heavily on Bootstrap can sometimes make it harder to understand what is actually happening behind the scenes. While the framework simplifies many tasks, I think having a solid understanding of HTML and CSS remains important. Otherwise, it becomes difficult to troubleshoot problems or customize layouts beyond what Bootstrap already provides.

For that reason, I believe developers should first become comfortable with the fundamentals before depending too heavily on a framework.

## Conclusion and Use of AI

Overall, my experience with Bootstrap 5 has been both challenging and rewarding. Although I initially found it more difficult than writing raw HTML and CSS, I now better understand why UI frameworks are commonly used in professional software development. They provide consistency, responsive design, reusable components, and improved collaboration between developers. While they require time to learn and may sometimes feel restrictive, the long-term benefits often outweigh the initial frustration.

I still believe there are situations where writing raw HTML and CSS is the better approach, particularly for smaller projects or when complete customization is needed. However, for larger projects involving multiple developers, Bootstrap provides a level of organization and efficiency that would be difficult to achieve by writing everything from scratch. Like many tools in software engineering, UI frameworks are not necessarily easier—they simply solve a different set of problems once you understand how to use them.
