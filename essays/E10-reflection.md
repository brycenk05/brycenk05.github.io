## Introduction

  Prior to starting out with TypeScript and even JavaScript for that matter, I had little experience with the language, having only experienced Java, C and C++ in the past. However, I was familiar with certain functions and how they were referred to in this language, for one the command to print out to the console was much easier to memorize especially compared to languages such as Java. With all this in mind, I was not too worried as there was a sense of transferability with my prior experience. I did expect there to be a larger learning curve, but my previous background made digesting the details much easier than expected.

## Learning TypeScript

  While I was familiar with the basics, such as primitive types, I was surprised to see that evcerything was much more simplified. For example, allowing users to utilize implicit variables by just guessing based on what they set a variable to is a useful tool. Still allowing explicit typing like other traditional languages was also a nice inclusion. Additionally, a small detail I did prefer is that number type covering both integers and doubles, but above all, the static typing was very useful for finding bugs in my code, especially during the practice WODs where I would make some minor mistakes that I would sometimes overlook.
  
  With how simple and user friendly the language aims to be, I would say that there is no real downside to having this language for software engineering. Although, I feel that there are some complexity drawbacks such as additional syntax like interfaces and enums, I would say the positives outweigh the negatives, especially with the perk of static typing and making readability of the code much easier. In addition, interfaces can also help with structuring data in a program especially as they grow in size. For these reasons I would say that TypeScript is a strong language for software engineering. 

## Athletic Software Engineering through WODs

  Being that I struggle heavily with coding, specifically on where to start, going into the first two practice WODs was a nice change of pace, keeping concepts simple, while allowing me to familiarize myself with the TypeScript environment. While I haven't gone through vigorous practice, as I was able to solve the problems relatively fast, I still see the usefulness in redoing a problem even if you know the solution. Not to mention, I believe the stopwatch pushed me to at least build my code faster than I would have, instead of staring at the problem and trying to brainstorm the solution in my head. For future WODs I will no doubt be challenged even harder, but yet I am encouraged to keep pushing myself to become a faster coder, both in writing and when it comes to formulating a solution. 

## Conclusion and Use of AI

  Overall, I found this experience with TypeScript to be a great introduction. The lesson built off of familiar concepts while also adding a layer of "freshness." As someone who occasionally uses OpenAI's ChatGPT free model, I didn't find myself needing to refer for help when it came to coding. However, for this essay, I did feel some need to better organize my thoughts to better structure how I wrote this. In turn, I did utilize ChatGPT for providing a guideline as I shared my personal thoughts on TypeScript and if I had trouble remembering a concept, I would ask ChatGPT for the specific name of a function or feature. Although there will certainly be more difficult topics ahead, I feel better prepared to approach them after working with TypeScript and completing the practice WODs.
